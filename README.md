# internal_client
# Internal Client
Асинхронная Python-библиотека для взаимодействия микросервисов с API Gateway.
Предоставляет единый HTTP-клиент на базе `httpx`,
автоматически добавляет служебные заголовки и формирует JWT с контекстом пользователя.

## Возможности
- Асинхронные HTTP-запросы через `httpx.AsyncClient`.
- Автоматическое добавление заголовков `X-Service-ID`, `X-Service-Token` и `X-User-Context`.
- Формирование JWT с данными пользователя и сроком действия токена.
- Проверка обязательных пользовательских claims перед созданием JWT.
- Настройка таймаута HTTP-клиента.
- Логирование начала, успешного завершения и ошибок запросов.
- Обработка HTTP-ошибок через `raise_for_status()`.
- Повторное использование единственного экземпляра клиента в рамках процесса.

## Технологии
- Python 3.12+
- httpx
- PyJWT

## Установка
Библиотека устанавливается из приватного репозитория или локального проекта, используйте соответствующий адрес или путь.
```bash
pip install "git+ssh://git@<git-server>/<group>/initial-client.gitt@<tag>"
```
Замените <git-server> адресом Git-сервера, <group> — названием группы или организации, а <tag> — нужной версией библиотеки.

### Проверка установки
После установки проверьте, что библиотека импортируется:
```bash
python -c "from initial_client import InitialClient; print('Installation successful')"
```
Если команда завершилась без ошибок, библиотека доступна в текущем Python-окружении.

## Инициализация клиента
Для работы с библиотекой необходимо указать адрес API Gateway, идентификатор и токен сервиса, а также параметры формирования JWT.

```python
from initial_client import InitialClient

initial_client = InitialClient(
    base_url="http://gateway:8000",
    service_id="profile-service",
    service_token="your-service-token",
    gateway_name="api-gateway",
    access_token_expire_sec=300,
    jwt_secret="your-jwt-secret",
    timeout=10.0,
)
```

### Параметры конструктора

| Параметр | Тип | Описание |
|---|---|---|
| `base_url` | `str` | Базовый URL API Gateway |
| `service_id` | `str` | Идентификатор вызывающего сервиса |
| `service_token` | `str` | Секретный токен сервиса |
| `gateway_name` | `str` | Значение `aud` в JWT |
| `access_token_expire_sec` | `int` | Срок действия JWT в секундах |
| `jwt_secret` | `str` | Секрет для подписи JWT |
| `timeout` | `float \| httpx.Timeout` | Таймаут HTTP-клиента; по умолчанию `10.0` секунды |


## Выполнение HTTP-запросов
Для отправки запросов используется асинхронный метод `request()`.

```python
response = await initial_client.request(
    method="GET",
    path="/api/profile",
    user_context=user_context,
)
```
### Параметры метода

| Параметр | Тип | Описание |
|---|---|---|
| `method` | `str` | HTTP-метод: `GET`, `POST`, `PATCH`, `DELETE` и другие |
| `path` | `str` | Путь API относительно `base_url` |
| `user_context` | `str` | JWT с контекстом пользователя |
| `params` | `dict[str, int] \| None` | Query-параметры запроса |

Пример получения JSON:

```python
response = await initial_client.request(
    method="GET",
    path="/api/profile",
    user_context=user_context,
)

data = response.json()
```

## Формирование пользовательского контекста
Библиотека предоставляет методы для проверки claims и создания JWT.
Ожидается словарь с тремя обязательными полями:
```python
claims = {
    "id": 123,
    "is_active": True,
    "is_superuser": False,
}
```

Создание JWT:
```python
user_context = initial_client._build_user_context(claims)
```
В сформированный токен входят следующие поля:

| Claim | Описание |
|---|---|
| `sub` | Идентификатор пользователя, преобразованный в строку |
| `is_active` | Статус активности пользователя |
| `is_superuser` | Признак суперпользователя |
| `aud` | Аудитория токена — `gateway_name` |
| `exp` | Время истечения токена в формате Unix timestamp |
Токен подписывается алгоритмом `HS256`.

Метод `_build_user_context()` является внутренним методом библиотеки. Он показан здесь для демонстрации механизма формирования JWT. Внешний сервис должен передавать данные пользователя в соответствии с согласованным контрактом между сервисами.

### Проверка claim
Библиотека проверяет:
- наличие всех обязательных полей;
- что `id` не равен `None` и не является булевым значением;
- что `is_active` и `is_superuser` имеют тип `bool`.

При некорректных данных выбрасывается `ValueError` или `TypeError`.

## Заголовки запросов
Каждый запрос автоматически получает следующие заголовки:
| Заголовок | Назначение |
|---|---|
| `X-Service-ID` | Идентификация вызывающего сервиса |
| `X-Service-Token` | Аутентификация сервиса |
| `X-User-Context` | Пользовательский контекст в виде JWT |

Добавлять эти заголовки вручную при использовании `request()` не требуется.

## Таймауты

По умолчанию HTTP-клиент использует таймаут `10` секунд.
Можно настроить его при создании экземпляра:

```python
initial_client = InitialClient(
    base_url="http://gateway:8000",
    service_id="profile-service",
    service_token="your-service-token",
    gateway_name="api-gateway",
    access_token_expire_sec=300,
    jwt_secret="your-jwt-secret",
    timeout=20.0,
)
```
Также HTTPX поддерживает отдельные таймауты подключения, чтения, записи и ожидания соединения из пула:

```python
import httpx
timeout = httpx.Timeout(
    connect=3.0,
    read=10.0,
    write=10.0,
    pool=5.0,
)
```
Передайте объект `timeout` в конструктор клиента.
Если вызывающему коду требуется ограничить общее время выполнения операции, это можно сделать с помощью `asyncio.timeout()`:

```python
import asyncio

async with asyncio.timeout(5.0):
    response = await initial_client.request(
        method="GET",
        path="/api/profile",
        user_context=user_context,
    )
```

## Обработка ошибок

Библиотека вызывает `response.raise_for_status()` после выполнения запроса. Если сервер возвращает HTTP-ошибку, HTTPX выбрасывает соответствующее исключение.
Ошибки запросов также записываются в лог самой библиотеки.

## Закрытие клиента

После завершения работы необходимо закрыть HTTP-клиент, чтобы освободить сетевые ресурсы.
```python
await initial_client.close()
```
В приложении с управляемым жизненным циклом рекомендуется вызывать `close()` при завершении работы сервиса, например в `lifespan` FastAPI.

## Особенности использования

- `InitialClient` реализован как Singleton: в рамках одного процесса повторное создание объекта возвращает тот же экземпляр.
- Конфигурация применяется при первой инициализации экземпляра. Последующие вызовы конструктора не обновляют параметры существующего клиента.
- Не рекомендуется создавать отдельный экземпляр клиента для каждого HTTP-запроса.
- При использовании нескольких конфигураций или нескольких API Gateway текущая реализация Singleton требует доработки.
- JWT подписывается общим секретом. Секрет должен быть одинаково настроен на стороне, которая проверяет подпись токена.
- Секреты сервисов и JWT нельзя выводить в логи или хранить в открытом виде в репозитории.
